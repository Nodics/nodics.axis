# Editorial editor

The schema renderer opens this editor for the canonical Editorial article schema,
including News, Blogs and the article workspace. Editorial owns draft persistence,
business revisions, language policy, review, archive and publication correlation.
Axis consumes declared aggregate APIs and never saves the root and translation
with separate generic writes.

The exact admitted Staged source supplies a versioned workspace with saved copy,
configured languages, authorized operations and inert English/Arabic presentation.
CMS may override the same `editorialAuthoringPresentation` string contract through
the Workbench component properties. Partners may extend the closest renderer and
typed client; retain owner API declarations, source/actor retirement, acknowledgement
checks and backend enforcement. Do not add a browser workflow, permission registry,
database connection or publication authority.

Edits remain visible across preview. Saving sends one owner command for changed
fields and the selected language. Unsupported structured bodies stay read-only;
unchanged body and SEO extension fields are preserved. Missing languages start
with empty copy. Saved incomplete translations remain drafts under owner policy.
Unsaved edits block lifecycle actions and language changes, and closing requires
explicit discard confirmation. Refresh also confirms replacement of an open draft.

An uncertain save holds its original command reference and copy. Inspect reads the
original command without replay. Unknown or changed outcomes remain held until
explicit inspection and replacement with the saved article. A successful command
requires exact identity, revision, state, saved copy and retained publication
reference. Changing actor, tenant, project or source retires pending callbacks.
Denied or unavailable owner reads disable editing; no generic fallback is allowed.

The layout uses responsive stacks and grids; language selection does not require
changing the global interface language. Native desktop/mobile and theme verification
remain separate from unit evidence. Native intake, publication and public delivery are distinct acceptance gates.

Run the focused `test/operations/editorial` suite, then the repository `npm run verify`.
`editorialAuthoringClient.test.ts` checks source scope, declared transport, receipts
and inspection; `EditorialArticleWorkbenchDetail.test.tsx` checks draft/preview,
one-command save, uncertainty, language selection, structured-body preservation,
discard confirmation and old-actor retirement. Withdrawal tests independently
check the actual publication revision and retained older-source references.
Canonical backend/business guidance belongs to the Editorial module README and
contracts, and the CMS-owned content documentation pack.

A pending owner lifecycle command blocks editor changes, archive, close and refresh.
The withdrawal component stays mounted to consume its exact owner receipt. Successful
withdrawal replaces prepared evidence with the acknowledged state/revision, including
when a newer draft remains unchanged. Incompatible completion clears the obsolete
prepared snapshot and requires fresh inspection. The label distinguishes published
source revision from the current working revision. Header, chips, controls and featured
panels consume the existing Axis theme tokens for light/dark contrast.

The owner may retain a bounded `publicationIntent` before target work. Its exact code
and source revision are separate from an older retained Online reference. A pending
intent disables copy/archive commands and displays both references with independent
owner inspection links. Explicit resume uses the same declared publish action and
the original retained code; it never creates a replacement request or performs
automatic recovery. Failed lifecycle operations remain with nPublish recovery.
Pending-request copy and action labels use the same typed English/Arabic owner
presentation contract, which CMS can override without changing authority.

Content language supplies HTML language and writing direction independently of
interface language. Public title/summary/story/takeaways and localized text inputs
use the shared localization direction utility. Interface captions and empty-state
messages keep the interface language; URL slugs keep left-to-right URL presentation.
Changing the content language clears the previous save notice. These attributes
neither grant a language nor change saved copy, locale policy or the global UI.

Current deployment is separate owner-read evidence (DEPLOYED/NONE/UNKNOWN), not an
article publication-state override. Display its exact request/source revision and
inspection link while preserving latest article publication history. Delivery
windows, embargo and access rules still govern public visibility. A restored copy
can prepare withdrawal against its own current nPublish revision; the owner
rechecks deployment/source/activation identity and preserves newer working copy.
Unknown deployment does not hide saved copy or claim absence. Archive admission
remains with the owner and requires verified absence for retained publications.
After confirmed withdrawal, refresh the workspace rather than retaining stale
deployment evidence. Scope changes retire pending inspections/acknowledgements.

A verified NONE deployment on a newer draft removes irrelevant withdrawal
controls. A PUBLISHED source may inspect its retained request for terminal
reconciliation; a rolled-back request with no deployment shows history without
another withdrawal confirmation. Latest publication history is preserved.

Initial owner reads show loading/recovery rather than empty translation placeholders.
Archive and save retain separate progress labels, and a closing confirmation keeps
its reviewed intent throughout the exit animation. Busy commands never masquerade
as unsaved edits. Customize presentation through the existing owner/CMS strings;
keep operation/receipt guards and source retirement intact. The draft journey tests
cover delayed reads, failed-read recovery and delayed archive acknowledgements.

Inline article images use the workspace's optional `mediaIntake` purpose and
bounded EN/AR copy. Layer `editorial.authoring.mediaIntake` in the owner; Media
continues to configure safe contexts, folders, formats and file policy. The closest
`MediaImageIntakePanel`/typed client can be extended for presentation without
copying a browser storage registry, credentials, permission rules or customer
folder map. The panel reviews policy before one explicit upload, and requires a
separate use-image action before changing the draft. Save persists that association;
normal Media/article review and publication remain separate.

The client binds an original generated code, SHA-256 and actual file descriptor,
requires positive owner evidence and exact persisted metadata, and exposes no
provider paths or delivery URLs. An uncertain upload retains its reference and
allows only original read-only inspection; missing/changed/nonversioned evidence
never resends bytes. Busy commands lock article actions and close, and actor or
exact Media source changes retire late results. The panel is responsive and uses
theme tokens; native verification is required separately from mocked tests.
`mediaImageIntakeClient.test.ts` covers transport, policy and receipts;
`MediaImageIntakePanel.test.tsx` covers explicit association, held unknown outcomes,
no replay, denied qualification and retired callbacks. The older standalone Media
upload wizard is a separate journey and is not qualified by these tests.

Repeated identical read/save/controller lifecycle feedback is displayed once;
independent messages remain visible. This is display deduplication only, without
classifying English wording, changing error authority or relaxing held-command
inspection and refresh requirements.

Confirmed workspace reads and acknowledged saved/archived receipts retire obsolete
Workbench lifecycle feedback through its optional local controller callback. The
callback cannot reset a pending owner mutation. Failed reads and unconfirmed
commands preserve their feedback and holds. A stable callback reference prevents
mutation-state changes from triggering replacement reads or discarding draft copy.

Saved featured-image readiness comes from the Editorial workspace and Media's retained-version/physical-byte qualification. The detail view shows owner guidance, holds submit/publish for unqualified images, and reuses the existing exact authorized Media inspection handoff in a separate tab. Dirty image selections must first be saved. Image preview URLs never establish readiness or grant publication rights.
